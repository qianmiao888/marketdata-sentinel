# 掌握项目的关键面试问答

1. **一条记录怎样流转？** CSV 原始行与 manifest 校验值 → 解析 UTC 与精确小数 → 隔离无效行、保留冲突证据 → 版本内幂等存储 → 有界 API 查询 → 规则报告 → 共用事实对象 → 中英说明与下载。可沿 `pipeline`、`service`、`investigation`、`communication` 四个模块演示。
2. **为什么不用模型算数？** 精确指标由后端 Decimal 和规则产生，模型只能组织受约束证据；本次业务说明使用确定性模板。没有实测模型效果提升。
3. **如何防止旧结论混到新窗口？** 报告固定来源、版本、UTC 窗口；UI 查询键还包含问题与模式。改变参数后旧结果和下载消失；恢复接口从报告推导上下文，拒绝无关记录关联。
4. **恢复为什么不更新原版本？** 保留故障证据，重放原始输入得到内容寻址的完整版本。原始完整版本已存在时复用它；恢复记录与新核验报告仍记录本次动作。
5. **检查通过可以发公告了吗？** 不能自动批准。只能说已实现检查未发现问题；仍需检查业务语境、范围、来源、数字和双语表达，并人工校审。
6. **ETH 与 USDT 有什么区别？** 本案例 base volume 是 ETH 数量；quote volume 为 USDT 数量。合成 DEX token0 使用 USDC 单侧绝对数量，不能把任何一个直接写成 USD。
7. **本次发现并修正了什么？** 新增 PostgreSQL 测试初次有一个断言错误地要求与 SQLite 相同尾零位数，改为 Decimal 等值判断；每个导出仍保留自身报告精确字符串。浏览器自检将普通流程中的 JSON 发现详情改为可读缺失时间列表。
8. **做过真实用户测试吗？** 没有。已准备统一脚本、匿名记录、分类及修改/复看模板，真人使用验证待完成。代理操作不是用户研究结果。
9. **最大的工程取舍？** 继续 Streamlit 与既有数据库/API；用现有证据表保存恢复回执，没有新建工单平台。适合单人本地演示，未提供认证、多人协作、分布式任务锁或生产 SLA。
10. **哪些能力仍没验证？** 真实 DEX 历史采集、真实模型评测、Docker 运行、远程 CI 和真人理解；不能从离线通过推断这些能力。
