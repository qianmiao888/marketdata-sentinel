# 真实使用测试准备

**真人使用验证待完成。没有参与者、访谈原话或任务结果。** 自动化测试、代理浏览器验收和内容自检不计为真人验证。

目的：观察读者能否判断数字能否引用、找到依据、解释恢复边界。可邀请 3–5 名自愿参与者，尽量包含不写代码但接触过 Web3 的读者；这是找问题的小样本，不做统计效果推断。尚未发出邀请。

## 主持人统一脚本

开场：“这是历史数据演练，不需要账户、钱包或资金。我们观察页面和说明是否清楚，不评价你的能力。你可以随时停止，记录只用匿名编号。是否同意匿名记录？”不同意则停止记录，不收集不必要的个人信息。

固定起点：启动工作台，使用缺失演练版本、默认一小时 UTC 窗口；记下页面代码版本和报告 ID。不要提前讲解答案。

1. “请判断当前数字能否作为完整时间窗口的成交数量直接引用，并说明原因。”
2. “请找到支持判断的原始依据，并说明其中一个数字的单位。”
3. 允许参与者操作恢复：“请解释恢复结果证明了什么，还有什么不能确定。”
4. “哪一句或哪一步最困惑？如果转述给同事，你会怎样说？”

任务记录为：独立完成 / 经提示完成 / 未完成 / 未执行；分别保存任务表现、主持人提示和自愿原话。不给未执行项记零分，不计算虚构满意度、节省时间或转化。

问题分类：导航与发现性 / 数字与单位 / 来源与证据 / 演练与因果误读 / 状态与确定程度 / 翻译与遗漏 / 其他。严重程度按是否导致错误引用、是否阻断任务、是否仅增加理解成本填写。
